# 场景资产制作与放行

场景资产规划、空间预资产和正式场景资产包是三个不同状态。台账只说明需要什么；空间预资产证明镜头可以在该空间中成立；正式资产包才是关键帧、合成和视频生成的画面来源。

## 第一阶段：场景空间预资产

在 Scene Plan 批准后、镜头表和 Storyboard 定稿前建立。它可以是平面图、灰模、低成本草图、简化 2.5D/3D 或占位场景，但必须锁定：

- `scene_id`、坐标原点、轴向、单位和关键尺度；
- 出入口、墙面、地面、窗户、关键固定设备和动作接触点；
- 角色活动区域、Blocking、通道、遮挡和可触达关系；
- 180 度轴、屏幕方向和候选摄影机 Setup；
- 固定环境与动态环境的边界；
- 空间未知、容差和仍需验证的项目。

通过状态为 `LAYOUT_APPROVED`。它允许进入镜头表、Storyboard 和 Animatic，但仍是 `PLACEHOLDER` 或布局证据，不得直接作为正式场景母版。

## 第二阶段：正式场景资产包

Animatic 达到 `LOCKED_FOR_PRODUCTION` 后，根据已经需要的镜头、景别、机位和运动范围制作，避免在剪辑结构尚未确定前投入昂贵最终资产。正式包可采用固定底板、分层 2.5D、3D、几何重投影或混合方式，至少锁定：

- 场景正式母版、材质、关键尺度与空间母版版本；
- 固定设备身份、坐标、旋转、尺寸和容差；
- 已批准 Setup 的摄影机位姿、焦距/FOV、焦点和可见范围；
- 干净底板及角色离开后会露出的区域；
- 前景、中景、背景、遮挡层及可用的深度/几何/蒙版；
- 静态保护区、允许变化区和登记的环境动态区；
- 环境动态的独立图层/受控模拟区域、蒙版、方向、速度、强度与相位基线；
- 不含角色和活动道具的环境动态预演，以及角色/物体与环境反应耦合计划；
- Light State、天气、时间和 Look 参考；
- 画幅、分辨率、色彩空间和计划后期；
- 资产 ID、版本、文件、SHA-256、资产清单摘要和批准证据。

通过状态为 `ACCEPTED`。关键帧、生成交接包和正式视频只能引用这个状态的场景包。

## 放行边界

- Storyboard 可使用 `LAYOUT_APPROVED` 的预资产；正式关键帧不可。
- 正式场景资产不能在关键帧制作时由模型顺便重绘。关键帧只允许复用、投影、渲染、合成或在登记区域局部修改场景资产。
- 新 Setup 可以产生新投影，但必须继承同一空间母版和场景身份。
- 固定底板镜头优先交付 clean plate、遮挡层和允许变化蒙版；移动摄影机优先交付几何、深度、摄影机轨迹和视差依据。
- 如果 Animatic 改变景别、机位、动作范围或可见区域，正式场景包必须重新检查覆盖范围。
- 可见动态环境的正式包必须先通过无角色环境预演；预演未通过时，不得用加入角色后的正式生成来试错。
- 正式场景包升级时，对所有引用旧包的 Storyboard、关键帧、视频候选和通行证做依赖影响分析。

## 验收

使用 `assets/templates/scene-asset-package.json`。空间预资产运行：

```bash
python3 scripts/validate_scene_asset_package.py <包.json> --target layout
```

正式包运行：

```bash
python3 scripts/validate_scene_asset_package.py <包.json> --target final \
  --manifest <资产清单.json> --root <项目资产根目录>
```

机器校验只证明结构、身份和文件证据闭合；构图、设计质量、材质、灯光和空间可用性仍需实际查看资产及 Previs。
