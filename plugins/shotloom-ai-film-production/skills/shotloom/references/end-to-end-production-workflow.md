# 端到端电影化 AI 视频制作流程

本流程把故事、剧本、分镜、Animatic、AI 生成和后期连接为一条可追踪链。按项目复杂度裁剪产物，但不得跳过会让下一阶段失去可靠依据的决策。

## 三层真相来源

- **叙事真相**：故事开发、正式剧本和剧本拆解，回答发生什么、为什么发生、谁参与和需要哪些资产。
- **剪辑真相**：场景计划、镜头表、Storyboard 与 Animatic，回答观众何时看到什么、镜头持续多久、声音如何连接。
- **生产真相**：镜头通行证、批准资产、模型交接包和验收报告，回答如何生成、用什么证据放行以及最终接受哪个版本。

模型提示词和候选视频不是叙事或剪辑真相。更换 Gemini、MiniMax 或其他模型时，优先重编译模型交接包，不重写已经批准的剧本和镜头意图。

## 阶段 A：项目与故事开发

1. 使用 `project-brief.md` 明确受众、核心情绪、片长、画幅、交付渠道、预算和模型范围。
2. 使用 `story-development.md` 写一句话故事、梗概、角色目标、冲突、转折、结尾和 Beat Sheet。
3. 使用 `screenplay.md` 形成可生产剧本；场景标题、动作、对白、声音和必要转场必须可被拆解。

放行条件：故事因果成立；片长与叙事容量相称；主要角色、场景和关键道具有来源；高风险内容已登记。只有概念测试可以使用简化剧本，并必须标为 `PREVIS`。

## 阶段 B：剧本拆解与资产规划

1. 使用 `script-breakdown.json` 为 Sequence、Scene、Beat、角色、场景、道具、声音和效果建立稳定 ID。
2. 建立角色、场景、道具台账；区分占位资产和最终资产。
3. 记录模型风险：多人交叉、精细手部操作、文字、镜面、左右不对称、复杂连续动作和同镜换光。

放行条件：每个 Beat 可回指剧本；角色/场景/道具首次出现和状态变化明确；资产缺口与风险有负责人或缓解方案。

## 阶段 C：场景计划与覆盖设计

1. 使用 `scene-plan.json` 记录场景目的、入口/出口状态、情绪弧、目标时长、Beat 顺序、轴线、Blocking、光色、声音和覆盖方案。
2. 决定使用建立镜头、主镜头、正反打、双人、过肩、反应、插入或特写；只保留剪辑真正需要的覆盖。
3. 长镜头是明确的创作选择；同一场景默认允许正常切镜。

放行条件：每个 Scene 的 Beat 有画面承载；覆盖足以剪出目标叙事；没有互相冲突的空间、光线、角色或道具状态。

## 阶段 D：场景空间预资产

1. 根据批准的 Scene Plan 使用 `scene-asset-package.json` 建立 `LAYOUT` 阶段场景包。
2. 锁定坐标、关键尺寸、出入口、固定设备、动作区域、遮挡、可触达关系、候选摄影机 Setup 和环境动静边界。
3. 允许灰模、草图、低成本 2.5D/3D 或占位图，但必须标记为布局资产，不能继承为正式画面母版。

放行条件：状态为 `LAYOUT_APPROVED`；空间、比例、设备和摄影机位置能够支撑计划动作与覆盖；所有未知和容差已登记。没有已批准空间预资产，不进入正式镜头表和 Storyboard。

## 阶段 E：镜头表与 Storyboard

1. 使用 `shot-list.json` 为每个 Shot 写明目的、景别、Setup、预计时长、摄影机、动作、声音、转场、头尾余量和模型风险。
2. 使用 `storyboard-sheet.md` 绘制或引用面板；标出构图、运动箭头、角色/道具、对白/声音、时长和前后连接。
3. Storyboard 是剪辑设计证据，不要求达到最终画质。关键状态图不能自动代替完整 Storyboard；简单镜头可以一格，复杂动作应有多个必要面板。

放行条件：镜头 ID 唯一稳定；每个镜头服务明确 Beat；相邻镜头的轴线、视线、屏幕方向、动作、光线和声音能够连接；计划转场有足够头尾余量。

## 阶段 F：Animatic 与临时声音

1. 使用 `animatic-timeline.json` 将 Storyboard、占位视频、临时对白、Room Tone、动作声和音乐 Cue 放入时间线。
2. 实际播放检查叙事可读性、节奏、停顿、反应镜头、信息重复、镜头时长和声音桥。
3. 先修改低成本 Animatic，再生成昂贵正式镜头。锁定初剪后将状态设为 `LOCKED_FOR_PRODUCTION`；这不是最终 Picture Lock。

放行条件：场景总时长在目标容差内；所有正式 Shot 已在时间线中占位；关键对白和动作有足够时间；需转场或剪点微调的镜头具备头尾余量；缺失资产和高风险镜头已标记。

## 阶段 G：正式场景资产包

1. Animatic 达到 `LOCKED_FOR_PRODUCTION` 后，根据实际镜头、景别、Setup、可见范围和运镜制作 `FINAL` 阶段场景资产包。
2. 交付场景正式母版、空间母版、固定设备、批准 Setup、干净底板、必要分层/遮挡/深度或几何、环境动态、Light State、Look 和技术基线。对可见动态环境，单独交付动态区域图层/蒙版、方向、速度、强度、相位基线和反应耦合计划。
3. 资产包引用已验收资产清单；文件、版本和 SHA-256 闭合。角色和活动道具不得烘焙进需要复用的场景底板，除非镜头制作方法明确要求并有独立干净版本。

放行条件：场景资产包状态为 `ACCEPTED`；覆盖所有批准镜头需要的画面范围；空间、固定设备、摄影机和角色触达通过实际查看或 Previs；静态保护区与允许变化区明确。可见动态环境已完成不含角色的环境动态预演，证明自然运动、静态锚点与相位连续性成立。正式关键帧不得引用 `LAYOUT_APPROVED` 占位资产。

## 阶段 H：模型能力配置与镜头路由

1. 使用 `model-capability-profile.json` 记录当前实际可用模型，而不是凭产品名称猜能力。
2. 至少记录：提供商、模型 ID、验证日期、输入类型、参考限制、首尾帧/延长能力、时长、画幅、分辨率、帧率、声音、摄影机控制、成本、等待时间和已知失败模式。
3. 根据镜头需求选择模型。连续性要求高但模型缺少视觉参考或续接能力时，改用分层合成、3D/2.5D、局部编辑或其他模型；不要降低镜头标准来迁就模型。
4. 从同一镜头母规格编译模型专用交接包。模型专用提示词只能改变表达方式，不得覆盖批准资产、空间、动作、摄影机和剪辑意图。

能力配置必须带 `verified_at` 和 `verification_status`。未验证或已过期的能力只能用于测试，不得作为正式放行依据。

## 阶段 I：正式镜头五道关卡

对进入生产的每个 Shot 执行 Shotloom 五道关卡，其中第二关 B 为环境动态控制子关卡：场景母版 → 动态分层 → 无角色环境预演 → 角色/环境反应合成 → 完整镜头验收。Storyboard 与 Animatic 提供镜头意图和时长基线，通行证负责生产证据。若正式候选迫使镜头目的、时长或剪辑结构变化，应退回镜头表/Animatic，而不是仅在提示词中暗改。

## 阶段 J：生成、验收与返工

1. 按模型交接包生成，保留模型 ID、参数、输入版本、输出版本和重试轮次。
2. 以目标帧率实际观看，检查关键帧、角色/物体运动、环境运动、动作驱动的环境反应、摄影机、声音、剪点、跨镜头/分段相位、静态锚点和技术缺陷。
3. 只接受能回指通行证和资产证据的版本。同一缺陷重复出现时退回造成问题的阶段，不无限抽卡。
4. 连续 Take 的后续技术 Segment 使用验收通过的真实尾帧和尾部窗口；正常切镜不复制上一镜头像素。

## 阶段 K：剪辑、后期与交付

1. 用正式候选替换 Animatic 占位素材，保持 Shot ID、时间线位置和批准时长；任何结构性变化返回 Animatic 审核。
2. 后期优先保留可编辑性：干净画面、独立字幕、分轨声音和必要的场景/角色/道具层。不要在可编辑母版中无依据烘焙字幕、音乐或不可逆效果。
3. 完成剪辑、调色、声音、字幕和交付 QC。最终成片以时间线和交付规格为准，不以单镜头 `ACCEPTED` 代替全片验收。

## 变更传播

- 故事或剧本改变：重新检查受影响 Scene、Beat、Shot、资产、Animatic 和通行证。
- Scene 目标或时长改变：重新检查覆盖方案、镜头表和 Animatic。
- 场景空间预资产改变：重新检查 Blocking、摄影机 Setup、镜头表、Storyboard 和 Animatic。
- Storyboard/镜头表改变：重新检查相邻连续性、资产需求、模型路由和通行证。
- Animatic 剪点改变：重新检查正式镜头时长、头尾余量、声音桥和时间线替换。
- 正式场景资产包改变：使引用旧包的关键帧、候选视频和通行证失效，并检查新资产是否仍覆盖全部批准 Setup。
- 模型配置改变：只重编译受影响交接包；除非能力限制暴露设计不可拍，否则不改叙事与剪辑真相。
- 资产、空间或 Light State 改变：使所有引用旧版本的关键帧、候选视频和通行证失效。

## 模板使用顺序

`project-brief.md` → `story-development.md` → `screenplay.md` → `script-breakdown.json` → `scene-plan.json` → `scene-asset-package.json (LAYOUT)` → `shot-list.json` → `storyboard-sheet.md` → `animatic-timeline.json` → `scene-asset-package.json (FINAL，含环境动态分层与无角色预演)` → `model-capability-profile.json` → `shot-production-pass.json` → `generation-brief.md` → 完整镜头验收与后期。
